# 서울시 전세거래 취약도 조기경보 모델 — 분석 설계서

## 0. 한 줄 요약

> 구 단위로 검증된 "전세사기 위험 특징"을, 동·격자 단위로 내려서
> **아직 피해 통계에 안 잡혔지만 같은 특징이 쌓이고 있는 다음 위험지역**을 찾는다.

GeoPath 수상작의 공간분석 골격(격자 DB → 정규화 → KDE → K-Means → 중첩)을
전세 주제로 이식한다.

---

## 1. 핵심 설계 원칙 (방식 A)

### 1-1. 두 시점을 분리한다

| 구분 | 데이터 | 시점 | 역할 |
|------|--------|------|------|
| 입력 X | 전세가율, 신축빌라, 공시지가 괴리, 청년수요 | **최신(2025~2026)으로 통일** | 현재 거래환경 진단 |
| 검증 Y | 자치구별 전세사기 피해건수 | 2023~2025 | 모델 방향 검증(채점 기준) |

**왜 입력을 최신으로 통일하나**: 캠퍼스 반출 데이터의 연도가 제각각이고,
특히 건축물대장이 2016년본이라 과거 시점 스냅샷을 못 맞춘다.
2026년 현재 시점으로 전부 통일하면 연도 미스매치 문제가 사라진다.

**왜 피해 데이터는 과거여도 되나**: 전세사기 피해는 계약 후 2~3년 뒤 통계에 잡힌다.
2023~2025 피해 다발 구는 그 전에 위험 신호가 쌓였던 곳이다.
따라서 피해 CSV는 "현재 모델이 기존 핫스팟을 제대로 짚는지" 검증하는 닻으로 쓴다.

### 1-2. 구 → 동 → 구 왕복 구조 (목표 직결)

```
[구 단위]  2023~25 피해 많은 구 ──특징 분석──> "이 특징들이 위험과 연결" (검증됨)
                                                     │
                                          같은 특징을 동·격자 단위로 계산
                                                     ▼
[동 단위]  취약도 점수 높은 동/격자 = "다음 위험 후보지" (핵심 결과물)
                                                     │
                                   동 점수를 구로 합산 ──> 피해 많은 구가 실제로
                                                          높게 나오나? (교차검증)
```

이 구조가 "동 단위 피해 데이터가 없다"는 한계를 정면 돌파한다.
동 단위 정답은 세상에 없으므로(개인정보), 구 단위 정답으로 검증하고
동 단위는 "구조적 위험 특징의 밀집도"로 정의한다.

### 1-3. 낙인 방지 표현

- (X) "전세사기 많은 동네"  →  (O) "전세거래 취약지역 / 예방자원 우선지역"
- 결과물 이름: **S-JVWI (Seoul Jeonse Vulnerability Warning Index)** 0~100점

## 2. 공간 단위 설계 (GeoPath 차용)

| 공간 단위 | 용도 |
|-----------|------|
| 건물/필지 | 전세가율, 신축여부, 공시지가 괴리 원천 계산 |
| **250m 격자** | 고위험 건물 밀집도, 신축빌라 KDE (메인 분석 단위) |
| 행정동(424개) | 인구·청년수요·정책자원 연결, 모델 학습 단위 |
| 자치구(25개) | 2023~25 피해건수 검증 단위 |

GeoPath는 100m 격자를 썼지만, 우리는 250m 격자 권장.
이유: 빌라 실거래·신축은 100m에서 데이터가 sparse(빈 격자 많음)해진다.
250m가 발표용으로 안정적. (코드에서 GRID_SIZE 파라미터로 조정 가능하게 설계)

## 3. 변수 설계

### 3-1. 핵심 파생변수 (입력 X)

| 영역 | 변수 | 계산식 | 데이터 출처 |
|------|------|--------|------------|
| 가격위험 | 전세가율 | 전세보증금 ÷ 매매가 × 100 | 국토부 실거래가(외부) |
| 가격위험 | 고전세가율 비율 | 전세가율 80%↑ 거래 / 전체 거래 | 국토부 실거래가(외부) |
| 가격위험 | 공시지가 대비 전세가 괴리 | 단위면적 전세가 ÷ 공시지가 | B020/B403 + 실거래가 |
| 건물위험 | 신축빌라 비율 | 준공 5년내 연립·다세대 / 전체 | 국토부 개방대장(외부, 최신) |
| 건물위험 | 연립·다세대 밀집도 | 격자 내 빌라 건물 수 | 국토부 개방대장(외부) |
| 수요위험 | 청년인구 비율 | 20~39세 / 전체 인구 | B031 |
| 수요위험 | 전입수요 | 전입자 수, 순이동 | B050 |

### 3-2. 검증변수 (Y)
- 자치구별 전세사기 피해건수 2023/2024/2025 (보유 CSV)

## 4. 분석 파이프라인 (단계별 = 스크립트 단위)

```
00_download_external.py   외부 데이터 자동 다운로드 (국토부 실거래가 등)
01_build_spatial_db.py    250m 격자 공간DB 구축 (총인구 0 격자 제거)
02_make_variables.py      건물/필지 → 격자·동 단위 변수 집계
03_jeonse_ratio.py        실거래가 결합 → 전세가율 계산 (핵심)
04_normalize_kde.py       MinMax 정규화 + KDE 밀도화
05_vulnerability_index.py S-JVWI 취약도 지수 산출 (가중합)
06_kmeans_cluster.py      K-Means 위험 유형 군집
07_validate_gu.py         동 점수 → 구 합산 → 피해 CSV 교차검증
08_detect_next.py         "다음 위험지역"(저피해·고위험 동) 탐지
09_visualize.py           Folium/GeoPandas 히트맵 + 이동지도
```

### 단계별 핵심 로직

**01 격자 DB**: 행정동 경계 shp(B294/B295 또는 SGIS) 안에 250m 격자 생성,
B031 인구로 총인구 0 격자 제거 → 분석 격자 확정.

**03 전세가율 (가장 까다로움)**:
국토부 실거래가는 매매/전월세가 별도 파일. 같은 건물·면적 매칭이 어렵다.
→ 동 단위 평균으로 집계: "동별 평균 전세보증금/㎡ ÷ 동별 평균 매매가/㎡"
→ 건물 단위로 정확히 매칭되는 케이스는 별도 정밀 변수로.

**05 취약도 지수 (초기 가중치, 발표 시 SHAP으로 역산 보정 명시)**:
| 변수 | 가중치 |
|------|--------|
| 전세가율 | 25 |
| 고전세가율 비율 | 15 |
| 공시지가 괴리 | 15 |
| 신축빌라 밀집도 | 15 |
| 빌라 전체 밀집도 | 10 |
| 청년인구 비율 | 10 |
| 전입수요 | 5 |
| (예비) | 5 |
| **합계** | 100 |

**07 검증**: 동별 S-JVWI를 구 단위 평균/상위비율로 집계 →
2023~25 피해건수와 Spearman 상관. 관악·강서·동작·금천이 상위에 오면 검증 성공.
표본 25개라 머신러닝 회귀는 부적절 → **상관분석 + 순위 일치도**로만 검증.
(머신러닝은 동 단위 424개에서 "전세가율 80%↑ 여부"를 Y로 한 분류에만 사용)

**08 다음 위험지역 정의 (명확한 기준)**:
> S-JVWI 상위 25% 이면서, 소속 자치구 누적피해 하위 50% 인 동
> = "예방자원 우선지역 (저피해·고위험)"

## 5. Claude Code vs 채팅 — 어디서 뭘 할까

| 작업 | 도구 | 이유 |
|------|------|------|
| 데이터 다운로드/전처리/집계 | **Claude Code** | 파일 입출력·반복·디버깅 |
| 격자 생성, 공간조인, KDE, 군집 | **Claude Code** | geopandas/sklearn 코드 |
| 변수 가중치·해석·발표 논리 | **채팅** | 판단·설명이 핵심 |
| "이 결과 맞나?" 검토 | **채팅** | 결과 해석 토론 |
| 캠퍼스 폐쇄망 작업 | (현장 PC) | 반출 데이터는 캠퍼스 안에서만 |

**중요**: 캠퍼스 반출 데이터(전세/공시지가/인구/이동통계)는 폐쇄망 안에서만 다룬다.
외부 데이터(국토부 실거래가, 개방대장)는 집/학교 PC에서 Claude Code로 처리 가능.
→ 두 환경의 결과물(동 단위 집계 테이블)을 동 코드(행정동 코드)로 join 하는 게 최종 통합.
