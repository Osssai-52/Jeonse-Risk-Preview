# 팀원 작업 가이드 — 캠퍼스 데이터 라인

## 네가 맡는 것 (한 줄)

캠퍼스 폐쇄망 안에서 전세·공시지가·인구·이동 데이터를
**행정동 코드 기준 동 단위 테이블 한 장**으로 집계해서 반출하는 것.
최종 산출물: `dong_campus.csv`

## 가장 먼저 (지금 당장)

**캠퍼스 이용신청을 건다.** 이게 전체 일정의 병목이다.
- 서울시 빅데이터 캠퍼스 이용신청 → 좌석예약 → 숙명여대 분원 방문
- 승인·방문에 며칠 걸리므로 다른 일보다 먼저 신청부터.
- 필요 데이터가 반출 가능 목록에 있는지 신청 시 확인:
  B031(거주인구), B050(인구이동), B020/B403(공시지가),
  전세 예측시세(연도 확인 필수), B294/B295(경계)

## 캠퍼스 방문 전 준비 (외부에서 가능)

1. 집계 스크립트를 **미리 짜둔다** (캠퍼스 안은 시간 제한 있음).
   가짜 샘플 데이터로 로직만 검증해두면 현장에서 빠르게 돌릴 수 있다.
2. 행정동 코드 체계 확인: adm_cd(행정동 코드) 자릿수, 법정동↔행정동 매핑 필요 여부.

## 캠퍼스 안에서 만들 변수 (전부 행정동 코드 키로)

| 변수명(컬럼) | 계산 | 데이터 |
|---|---|---|
| youth_ratio | 20~39세 인구 / 전체 인구 | B031 |
| inflow | 전입자 수 (또는 순이동) | B050 |
| gongsi_per_m2 | 동별 평균 공시지가(원/㎡) | B020/B403 |
| jeonse_campus | (전세 예측시세 쓸만하면) 동별 전세단가 | 전세 예측시세 |

**주의**
- 모든 결과 테이블에 `adm_cd`(행정동 코드)를 키로 남길 것. 이게 너 PC 결과와 합치는 연결고리다.
- 동 이름(한글)만으로 join하지 말 것 — 띄어쓰기·표기 차이로 깨진다. 코드로 맞춘다.
- 공시지가는 필지(번지) 단위라 동 평균으로 집계. 너무 큰/작은 이상치 제거.

## 반출할 것

`dong_campus.csv` — 컬럼: adm_cd, adm_nm, youth_ratio, inflow, gongsi_per_m2, (jeonse_campus)
이 파일 하나를 반출해서 메인 분석자(너 PC)에게 전달 → dong_master.csv로 합침.

## 분석이 도는 동안 병행할 것 (발표 라인)

캠퍼스 집계가 끝나면, 합류 후 분석은 메인 쪽에서 돌아가므로 이때 발표를 맡는다.

1. **근거 통계 최신 출처 재확인** (심사 방어용)
   - 전세사기 빌라 집중 비율 / 전세가율 80%=깡통 기준 / 피해 2~3년 후 집계
   - 2026년 현재 기준으로 최신 보도·통계 다시 확인 (오래된 수치 그대로 쓰지 말 것)
2. **발표 뼈대 작성** (GeoPath·회깅이들 구조 차용)
   - 서론(배경·문제) → 본론(데이터·방법·결과) → 결론(정책·기대효과·한계)
   - "이미 다 아는 얘기 아니냐" 방어 논리: 후행지표 vs 선행지표 프레임
3. **낙인방지 검수**: 슬라이드에 "전세사기 동네" 류 표현 없는지 확인.
   "전세거래 취약지역 / 예방자원 우선지역"으로 통일.
